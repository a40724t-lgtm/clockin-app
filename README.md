# 員工上下班打卡系統（第一版）

給 20 人以下小團隊使用的簡易打卡系統。員工用自己的手機打卡，管理員在後台查看紀錄、計算工時並匯出 Excel。
所有時間皆以台灣時間（Asia/Taipei）計算。

- 技術：Node.js + Express + SQLite（better-sqlite3），前端為純 HTML/CSS/JavaScript，不需要編譯打包。
- 介面：手機優先設計，字體使用 Noto Sans TC（Google Fonts，離線時自動改用系統字體），會依手機／電腦設定自動切換淺色或深色模式。
- 資料檔：`data/clockin.db`（第一次啟動時自動建立）

## 功能

**員工端（手機）** — 網址 `/`
- 點選自己的名字，輸入 4 位數 PIN 碼登入（同一支手機下次會自動記住）
- 大大的「上班打卡／下班打卡」按鈕，顯示目前時間
- 顯示今日狀態（未打卡／上班中／已下班、是否遲到、今日請假）與最近 14 天紀錄
- 「請假」分頁：申請請假（可附圖片／PDF）、申請「居家上班」或「公差」、查看申請狀態與審核意見、取消待審核的申請、查看特休剩餘
- 已核准居家上班／公差的日子，打卡頁會顯示「今天為居家上班，打卡將記錄 GPS 位置」，不需連公司 WiFi

**管理後台** — 網址 `/admin`，預設密碼 `admin1234`（請登入後立刻到「設定」修改）
- 今日總覽：誰已上班、誰遲到、誰請假、誰居家上班／公差、誰異地打卡、目前在班人數、待審核申請數
- 請假管理：審核請假、居家上班、公差（核准／退回＋意見）、全部紀錄篩選、行事曆（居家、公差以不同顏色顯示）、假別設定、每位員工的特休額度（詳見下方「請假」與「居家上班與公差」）
- 打卡紀錄：依日期區間與員工篩選，顯示每日上下班時間、工時、加班、遲到、缺卡，以及「居家」「公差」「異地打卡」標記與打卡位置的 Google 地圖連結
- 補登／修改／刪除打卡：必須填寫原因，紀錄上會留下「管理員於何時修改、原本是幾點」的註記；所有動作另存於「修改紀錄」
- 薪資統整（試算）：每位員工的月薪／時薪設定、固定津貼與扣項；依月份統整出勤、工時、平日／休息日加班、遲到早退、異地打卡、居家／公差、各假別請假與扣薪，算出應發、應扣、實發；可加獎金或其他加扣項、確認鎖定月份、匯出 Excel（詳見下方「薪資統整」）
- 薪資單 PDF＋Email：已確認的月份可把 PDF 薪資單（可用員工 PIN 加密）寄到員工 Email，有寄送紀錄與重複寄送提醒；員工也能在打卡頁下載自己的薪資單（詳見下方「薪資單 Email 寄送」）
- 員工管理：新增、編輯、移除員工、PIN 碼與 Email（移除後歷史紀錄仍保留）
- 打卡地點限制：可要求員工「連上公司 WiFi」且／或「人在公司附近」才能打卡（詳見下方說明）
- 被拒絕的打卡：員工因網路或位置不符被擋下的紀錄，管理員可在「打卡紀錄 → 被拒絕的打卡」查看
- 設定：公司名稱、上班時間（預設 09:00）、遲到寬限分鐘、午休時段（預設 12:00～13:00 不計工時，可關閉）、標準工時（預設 8 小時，超過算加班）、變更管理員密碼
- 匯出 Excel（.xlsx，含「每日工時」「個人合計」「打卡明細」「被拒絕的打卡」「請假紀錄」「居家上班與公差」六個工作表；個人合計含各假別請假時數、居家／公差天數、異地打卡次數；打卡明細含 IP、座標、距離、檢查結果、工作型態、異地打卡與地圖連結）或 CSV（可直接用 Excel 開啟，中文不亂碼）

**工時計算方式**
- 每日工時 = 每組「上班 → 下班」的時間加總，扣除與午休時段重疊的部分
- 第一次上班打卡晚於「上班時間 + 寬限分鐘」即標示遲到
- 工時超過標準工時的部分計為加班（僅供參考，實際加班費請依勞基法與公司規定計算）

## 打卡地點限制（公司 WiFi＋公司位置）

在後台「設定 → 打卡地點限制」可以分別開啟兩項檢查。**兩項預設都是關閉**；就算打開了，只要還沒設定好（沒有填 IP 或座標），系統也不會真的檢查，並會在後台上方顯示黃色警告，避免大家被鎖在門外。所有檢查都在**伺服器端**進行，員工無法只靠修改網頁繞過。

### 1. 公司網路（WiFi）檢查

網頁沒有辦法讀取手機連的 WiFi 名稱（SSID），所以改用「**公司網路的對外 IP**」判斷：
連上公司 WiFi 的手機上網時，對外都會顯示同一個公司 IP；用行動數據或在家裡，IP 就不同。

設定方式：
1. 管理員用連著**公司 WiFi** 的電腦或手機打開後台 →「設定」。
2. 按「**使用目前連線的 IP**」，系統會把目前的 IP 加到清單裡（也可以手動輸入，每行一個，支援網段寫法如 `203.0.113.0/24`，`#` 後面可寫備註）。
3. 勾選「只允許公司網路（WiFi）打卡」，按「儲存打卡限制」。

小提醒：
- 部分網路同時有 IPv4 與 IPv6，手機可能用 IPv6 上網。若員工在公司卻被擋，到「打卡紀錄 → 被拒絕的打卡」看他的 IP，再把那個 IP（或 IPv6 的 `/64` 網段）加入清單。
- 員工打卡頁會即時顯示「已連上公司網路」或「目前未連上公司 WiFi（IP：…）」。

### 2. 公司位置（GPS）檢查

員工按打卡時，手機瀏覽器會詢問「是否允許使用位置」，把經緯度與定位誤差送到伺服器，伺服器用 haversine 公式計算與公司座標的距離。

設定方式：
1. 人在公司時，在後台按「**使用目前位置**」，或自行輸入緯度、經度（可在 Google 地圖對公司按右鍵複製座標）。
2. 按「在地圖上查看」確認位置正確。
3. 設定允許範圍（預設 **150 公尺**）與定位誤差上限（預設 100 公尺；誤差太大時會請員工到窗邊再試）。
4. 勾選「只允許在公司附近打卡」，按「儲存打卡限制」。

被擋下時，員工會看到清楚的原因，例如：
- 「請連上公司 WiFi 後再打卡（目前連線 IP：…）」
- 「您目前距離公司約 820 公尺，需在 150 公尺內才能打卡。」
- 「您拒絕了定位權限…」「定位逾時…」「定位不夠精確…」

**重要：定位功能需要 HTTPS 網址**（`https://` 開頭）。Render、Railway 提供的網址都是 HTTPS；只有在本機 `http://localhost` 測試時例外。若用 `http://192.168.x.x:3000` 這種區域網路網址開啟，手機將無法定位，開啟位置檢查後員工會打不了卡。

### 3. 下班打卡規則（放寬／嚴格）

上班打卡一律依照上面的限制。下班打卡可以在「設定 → 打卡地點限制 → 下班打卡規則」選擇：

- **放寬（預設）**：符合以下任一項即為正常下班卡：
  - 連上公司網路（IP 在允許清單內），或
  - GPS 在公司座標的「放寬範圍」內（預設 **300 公尺**，可調整；定位誤差需在「定位誤差上限」內）。
  - 兩項都不符合時**仍可打卡**，但紀錄會標記紅色「**異地打卡**」，並記下 IP、GPS 座標與誤差（員工拒絕定位時註記「GPS 無法取得」）。管理員可在今日總覽、打卡紀錄（每日工時與打卡明細）看到標記與地圖連結，Excel 也有「異地打卡」欄與次數統計。
- **嚴格（同上班）**：下班也必須符合上面的限制，否則無法打卡（與舊版行為相同）。

若上面兩項限制都沒有開啟，打卡不做任何檢查，也不會標記異地打卡。

### 4. 管理員補登

管理員在後台補登或修改打卡**不受網路與位置限制**，紀錄上會註明「管理員補登／修改，不受網路／位置限制」，並保留修改原因。員工因手機沒電、定位失敗等原因打不到卡時，可以請管理員補登。

### 5. 部署在雲端時如何取得正確 IP

雲端主機前面會有一層反向代理，真實 IP 放在 `X-Forwarded-For` 標頭。本系統的處理方式：
- 在 Render、Railway 上會自動偵測，預設信任 **1 層**代理。
- 在自己電腦上預設只信任本機（127.0.0.1）的代理，外部連線帶來的 `X-Forwarded-For` 不會被採信。
- 可用環境變數 `TRUST_PROXY` 調整（數字代表代理層數，例如 `1`、`2`）。
- **經過 Cloudflare 時**（例如 SnapDeploy），代理層看到的是 Cloudflare 節點的 IP（如 `172.64.x.x`～`172.71.x.x`）。系統預設（`CLIENT_IP_HEADER=auto`）會在確認連線來自 Cloudflare 時，依序改讀 `CF-Connecting-IP` → `True-Client-IP` → `X-Forwarded-For` 最左邊的公開 IP；不是來自 Cloudflare 的連線則不採信這些標頭，避免有人偽造標頭繞過 WiFi 檢查。
- 也可用 `CLIENT_IP_HEADER` 強制指定：`none`（只用代理層數算出的 IP）、`x-forwarded-for`，或任何標頭名稱（例如 `x-real-ip`）。
- 打卡 WiFi 檢查、後台「使用目前連線的 IP」按鈕與登入錯誤鎖定都使用同一個判斷。

**部署後請檢查一次：** 用公司 WiFi 開啟 `https://你的網址/api/public/whoami`（或後台「設定」的「您目前的 IP」），確認 `ip` 和 https://ifconfig.me 顯示的一樣；`source` 會說明是從哪個標頭取得。若不一樣，請調整 `TRUST_PROXY` 或 `CLIENT_IP_HEADER` 後重新部署。

### 6. 限制（請務必了解）

- **公司 IP 可能會變**：一般家用／小型企業網路多半是「浮動 IP」，數據機重開或電信業者調整後 IP 就會改變，員工會突然全部打不了卡。建議向中華電信等業者申請**固定 IP**；若沒有，IP 變了就到後台重新按「使用目前連線的 IP」。
- **IP 檢查只能確認「用公司的網路上網」**：連上公司 VPN 或同一棟大樓共用網路的人也可能符合條件。
- **GPS 可以被偽造**：有心人可用模擬定位 App 假造位置，本系統無法完全防止。
- **室內定位可能不準**：在室內、地下室或高樓中，誤差可能達數十到數百公尺，可能導致在公司內卻被擋。可視情況調大允許範圍或誤差上限。
- 兩項檢查都能提高門檻，但不是百分之百防作弊；建議搭配主管日常確認。

## 請假

**員工申請**（員工頁 →「請假」分頁 →「申請請假」）
- 假別：特休、事假、病假、生理假、婚假、喪假、公假、其他（管理員可在後台新增、改名、停用；停用的假別不會出現在申請表，舊紀錄保留）
- 時段：全天（可跨多天）、上午、下午、指定時間（例如 10:00～15:00）
- 時數由系統依「設定」中的上班時間、標準工時、午休自動計算，並**跳過週六、週日**。以預設值（09:00 上班、8 小時、午休 12:00～13:00）為例：
  - 全天 = 09:00～18:00，扣午休 = 8 小時
  - 上午 = 09:00～12:00 = **3 小時**；下午 = 13:00～18:00 = **5 小時**（以午休為分界，因此上下午時數不同）
  - 若關閉午休，上午／下午各為標準工時的一半
  - 指定時間會自動扣除與午休重疊的部分；下班時間以外不計
- 必填原因；可附一個檔案（JPG、PNG、HEIC、GIF、WEBP 或 PDF，5MB 以內）。系統會檢查檔案內容是否真的是圖片／PDF，檔案存放在 `DATA_DIR/uploads/`，只有本人和管理員看得到
- 不能與自己已申請（待審核或已核准）的假期時段重疊
- 狀態：待審核 → 已核准／已退回；待審核時員工可以自行取消（已核准的請洽管理員）

**管理員審核**（後台 →「請假」）
- 待審核：側欄與今日總覽會顯示待審核數；可核准或退回，並留下給員工的意見
- 全部紀錄：依日期、員工、假別、狀態篩選
- 行事曆：月曆檢視誰在哪天請假（可篩選員工、顯示待審核）
- 已核准但臨時不休：在「全部紀錄」按撤銷並填寫原因，請假改為已取消、特休自動退回
- 每次核准、退回、撤銷、員工取消、特休額度調整、假別變更都會記錄在「修改紀錄」

**特休額度**
- 在「請假 → 特休額度與假別」為每位員工設定年度特休（以小時儲存，可用天數輸入，1 天 = 標準工時）
- 剩餘 = 年度額度 − 今年已核准的特休時數；審核中的特休會先從「可用」扣除，避免重複申請超過額度
- 額度依**曆年**（1/1～12/31）計算，以請假開始日所在年份歸屬；跨年**不會**自動結轉或重置，新年度請管理員重新設定額度
- **年資計算不是自動的**：填入員工到職日後，系統會依勞基法第 38 條（週年制）顯示「建議天數」，並提供「套用建議」按鈕，但不會自動更改額度。建議規則：滿 6 個月 3 天、滿 1 年 7 天、滿 2 年 10 天、滿 3 年 14 天、滿 5 年 15 天、滿 10 年起每年加 1 天（最多 30 天），依「今天」的年資計算。曆年制換算、按比例給假、未休特休折發工資等請依公司規定自行調整

**請假與出勤**
- 已核准的請假時段不算遲到：例如請「上午」假，下午 13:00 到班不算遲到；請 09:00～10:30，10:40 到班算遲到 10 分鐘；整天請假的日子不會出現遲到或缺勤
- 今日總覽會顯示請假中的人員；打卡紀錄的每日工時會標示請假，只有請假沒有打卡的日子也會列出（不計入出勤人日）
- Excel：「每日工時」多「請假」與「請假（小時）」欄；「個人合計」列出各假別的請假時數；「請假紀錄」列出期間內所有申請（含待審核、已退回、已取消）

## 居家上班與公差

員工在「請假」分頁按「**居家上班／公差**」申請，跟請假走同一個審核流程（後台「請假 → 待審核」）。

- **不是請假**：不扣時數、不扣特休，當天照常打卡並計算工時、遲到、加班。
- 以**整天**為單位，可跨多天（含週末，一次最多 31 天）；必填事由，公差可填地點（選填）。
- 同一段日期不能重複申請居家上班／公差；可以和請假同一天（例如上午請假、下午居家上班）。
- **只有「已核准」才生效**：待審核時打卡仍依公司網路／位置限制；員工打卡頁會顯示「今天的居家上班申請審核中」。
- 已核准的日子，上班、下班打卡都**不檢查公司 WiFi 與公司範圍**，但**一定要記錄 GPS**：系統會記下座標與誤差；若手機拒絕定位或定位失敗，會擋下並請員工到手機設定允許此網站使用位置（需 HTTPS 網址）。
- 員工打卡頁會顯示「今天為居家上班，打卡將記錄 GPS 位置」（取代 WiFi 警告）；打卡紀錄顯示「居家」「公差」標記。
- 後台：打卡紀錄的每日工時與打卡明細顯示「居家」／「公差」標記與 Google 地圖連結；行事曆以紫色（居家）、藍色（公差）顯示；Excel 有「工作型態」欄與「居家上班與公差」工作表。
- 管理員可撤銷已核准的申請（當天恢復公司網路／位置檢查），也可在「特休額度與假別」停用這兩種申請。

## 薪資統整（試算）

> ⚠ **試算僅供參考，請以會計／勞動法規為準。** 系統依打卡與請假資料自動計算，實際發薪前請由會計或負責人核對。

後台「**薪資統整**」有兩個分頁：

**薪資設定**
- 每位員工：計薪方式「**月薪**」或「**時薪**」、金額（NT$）、固定津貼（例如伙食津貼、職務加給）、固定扣項（例如勞保、健保自付額）。
- **勞健保自付額請依投保級距手動填寫**，系統不會自動計算級距或費率。
- 金額低於基本工資（2026 年：月薪 NT$ 29,500、時薪 NT$ 196）會顯示提醒。
- 計算規則：
  - **假別給薪比例**（每個假別可設照給／半薪／不給薪／自訂百分比，以及每年給薪上限天數）。預設值依勞基法、勞工請假規則、性別平等工作法：特休、婚假、喪假、公假（以及之後新增名稱含產假、產檢、陪產、公傷病假等）**照給**；**病假**（普通傷病，未住院）一年 **30 天內半薪**，超過部分不給薪；**事假、家庭照顧假不給薪**；**生理假半薪**；「其他」預設不給薪，請依實際情況調整。
  - **遲到／早退扣薪**：預設**關閉**。開啟後只依實際分鐘 × 時薪比例扣除（月薪制），**不做懲罰性罰款**；時薪制本來就依實際工時計薪，不另扣。
  - **提早到班不計工時**（預設開啟）：平日上班時間以前打卡的時間不算工時、不算加班。
  - **加班計算單位**：1 分鐘（預設，依實際分鐘）／15／30／60 分鐘，每天不足一單位不計。

**月份統整**（月份選擇器；每月 1～10 日預設顯示上個月）
- 每位員工：出勤天數、實際工時與計薪工時、平日加班（前 2 小時、第 3 小時起）、休息日加班、遲到／早退次數與分鐘、異地打卡次數、居家上班／公差天數、各假別請假時數與對薪資的影響、**應發／應扣／實發**。
- 計算方式：
  - 月薪換算時薪 = **月薪 ÷ 30 ÷ 8**。
  - **平日加班**（勞基法第 24 條）：超過標準工時的部分，前 2 小時 ×1.34、第 3 小時起 ×1.67。
  - **休息日加班**（勞基法第 24 條第 2 項）：系統**沒有國定假日行事曆**，因此**週六、週日上班一律視為休息日加班**：前 2 小時 ×1.34、第 3～8 小時 ×1.67、第 9 小時起 ×2.67。
  - **月薪制**：本薪 − 不給薪／半薪假別扣薪 −（遲到早退扣薪，若開啟）＋ 加班費 ＋ 固定津貼 ＋ 獎金等加項 − 固定扣項 − 其他扣項。
  - **時薪制**：計薪工時 × 時薪 ＋ 給薪假時數 × 時薪 × 給薪比例 ＋ 加班加成（平日 +0.34／+0.67；休息日 +0.34／+0.67／+1.67）＋ 津貼與加項 − 扣項。
  - 金額每一項四捨五入到元。
- 點「**明細**」可看每一筆計算式，並加入「**獎金／其他加扣項**」（含備註）；所有調整都記錄在「修改紀錄」。
- 「**確認 X 月薪資**」會**鎖定**該月份：保存確認當下的試算結果，之後修改打卡、請假或薪資設定都不會影響已確認的金額，也不能再新增或刪除調整項；需要時可「解除確認」（必填原因）。
- **匯出 Excel**：「薪資統整」總表＋每位員工一張「明細-姓名」工作表（應發、應扣、出勤摘要、假別明細、每日出勤）。
- **PDF 薪資單**：每列的下載圖示下載單一員工 PDF，「下載 PDF（全部）」下載整個月份的 zip（每人一個 PDF）。PDF 在伺服器產生（內建思源黑體／Noto Sans TC 字型，繁體中文不會變成亂碼），未確認的月份會標示「試算（未確認）」。
- 舊的網頁列印版仍可用 `/admin/payslip?month=YYYY-MM` 開啟（不再需要列印，建議改用 Email 寄送）。

## 薪資單 Email 寄送（PDF）

不用再印紙本：確認月份後，系統把每位員工的 PDF 薪資單寄到員工的 Email，員工也能在打卡頁自行下載。

1. **員工 Email**：到「員工管理」編輯每位員工，填寫 Email。示範員工預設是 `demo-a@example.com` 等**示範地址**（`example.com` 是保留網域），系統會自動略過，不會寄出。
2. **寄信設定**：「薪資統整」→「薪資設定」→「薪資單 Email 寄送設定」：SMTP 主機、連接埠、加密方式、帳號、密碼、寄件者名稱與 Email、信件主旨與內文範本（可用 `{姓名}` `{月份}` `{公司}` `{密碼說明}` `{實發金額}`）。
   - 密碼只存在伺服器，**不會再顯示**（畫面只顯示「已設定」），留空儲存表示不變更。
   - 「**測試連線**」只連線到 SMTP 伺服器（有填帳密就順便檢查登入），**不會寄出任何信件**；可用來確認主機商有沒有封鎖寄信連接埠。
   - 「**寄送測試信**」用已儲存的設定寄一封不含薪資資料的測試信給你指定的地址。
3. **PDF 開啟密碼**（預設：**員工 PIN 碼**）：寄出的 PDF 與員工自行下載的 PDF 會加密，需輸入員工的 4 位數打卡 PIN 才能開啟；也可改成「固定密碼」或「不加密」。管理員在後台下載的 PDF 不加密（公司留存用）。
4. **寄送**：只有「**已確認**」的月份可以寄送（未確認會擋下）。按「寄送薪資單」（全部）或每列的寄送圖示（單一員工），確認視窗會列出每位收件人的 Email、實發金額與狀態；**已寄過的員工預設不勾選**，若勾選會提醒「將再寄一次」，伺服器端也會擋下未確認的重複寄送。
5. **寄送紀錄**：每一封（時間、收件人、成功／失敗原因）都會記錄，月份統整的每一列顯示「已寄送 MM-DD HH:mm」或「寄送失敗」；「修改紀錄」也會留下寄送摘要。
6. **員工自行下載**：員工在打卡頁用 PIN 登入後，「**薪資單**」分頁列出已確認的月份，可下載自己的 PDF。

### 用 Gmail 寄信

1. 公司的 Google 帳戶需先開啟「**兩步驟驗證**」。
2. 到 Google 帳戶 →「安全性」→「**應用程式密碼**」（https://myaccount.google.com/apppasswords），建立一組密碼（16 個英文字母；貼上時有空格也沒關係）。
3. 寄信設定按「Gmail」快速套用：主機 `smtp.gmail.com`、連接埠 `465`、SSL/TLS。
4. 帳號填完整 Gmail 地址，密碼貼上**應用程式密碼**（不是平常登入的密碼），寄件者 Email 與帳號相同。
5. 「測試連線」→「寄送測試信」寄給自己確認。Gmail 個人帳號每天約可寄 500 封。

Microsoft 365／Outlook：`smtp.office365.com`、連接埠 `587`、STARTTLS（需管理員開啟 SMTP AUTH）。

### 用環境變數設定 SMTP（建議用在雲端主機）

免費雲端主機在重新部署、重新啟動或休眠喚醒後，資料庫會重置，在後台填的寄信設定也會消失。可改在主機的環境變數設定（設定 `SMTP_HOST` 後，後台的主機與帳密欄位會改為唯讀）：

| 環境變數 | 說明 | 範例 |
|---|---|---|
| `SMTP_HOST` | SMTP 主機 | `smtp.gmail.com` |
| `SMTP_PORT` | 連接埠（預設 465） | `465` |
| `SMTP_SECURE` | `true`＝SSL/TLS（465）；`false`＝STARTTLS（587）。未設定時 465 自動為 true | `true` |
| `SMTP_USER` | 帳號 | `yourcompany@gmail.com` |
| `SMTP_PASS` | 密碼／應用程式密碼 | （不要寫進程式碼或 Git） |
| `SMTP_FROM` | 寄件者 Email（預設同帳號） | `yourcompany@gmail.com` |
| `SMTP_FROM_NAME` | 寄件者名稱 | `我的公司 人事` |

> 有些主機商會封鎖對外寄信的連接埠（25／465／587）。部署後請先在後台按「測試連線」確認；若顯示無法連線，就只能換主機商或改用支援 HTTPS API 的寄信服務。

**薪資統整的限制**
- 沒有國定假日、例假與休息日的區分（週末都算休息日加班），也沒有颱風假、補班日；遇到國定假日出勤請以「其他加項」手動補差額。
- 加班以打卡計算（超過標準工時即算），不支援加班申請／核准制，也不支援補休。
- 月中到職或離職不會自動按比例計算月薪（會顯示提醒，請以調整項處理）。
- 平日加班費以本薪換算的時薪計算；若津貼屬於「經常性給與」而應計入加班費基數，請以調整項補差額。
- 生理假超過每年 3 日併入病假計算、產假依年資半薪等細節不會自動判斷，請依實際情況調整假別比例或以調整項處理。
- 不計算所得稅扣繳、勞退自提、二代健保補充保費。

## 在自己的電腦上執行

需要 Node.js 18 以上版本（https://nodejs.org 下載 LTS 版）。

```bash
cd clockin-app
npm install
npm start
```

打開瀏覽器：
- 員工打卡：http://localhost:3000
- 管理後台：http://localhost:3000/admin

同一個 Wi-Fi 下的手機，可以用電腦的區域網路 IP 連線，例如 `http://192.168.1.23:3000`。

可用的環境變數：

| 變數 | 說明 | 預設 |
|---|---|---|
| `PORT` | 埠號 | 3000 |
| `DATA_DIR` | 資料庫存放資料夾 | `./data` |
| `ADMIN_PASSWORD` | 第一次建立資料庫時的管理員密碼 | admin1234 |
| `NO_SAMPLE` | 設為 `1` 則不建立示範資料 | — |
| `TRUST_PROXY` | 反向代理層數或信任的 IP（決定如何讀取 `X-Forwarded-For`） | Render／Railway 上為 `1`，其他為 `loopback` |
| `CLIENT_IP_HEADER` | 從哪裡取得員工真實 IP：`auto`、`none`、`x-forwarded-for` 或標頭名稱 | `auto` |

## 部署到網路上（讓員工在外面也能打卡）

重點：SQLite 是一個檔案，**主機必須有「永久磁碟」**，否則每次重新部署資料就會消失。

### Railway
1. 把專案上傳到 GitHub。
2. 在 Railway 新增專案 → Deploy from GitHub repo，選擇這個專案。
3. 在服務中新增 **Volume**，掛載路徑設為 `/data`。
4. 在 Variables 加入 `DATA_DIR=/data`，以及自訂的 `ADMIN_PASSWORD`。
5. 在 Settings → Networking 產生網域，就會得到 https 網址。
6. 用公司 WiFi 登入後台，確認「設定」中顯示的 IP 正確，再開啟打卡地點限制。

### Render
1. 把專案上傳到 GitHub。
2. 在 Render 新增 **Web Service**，Build Command：`npm install`，Start Command：`npm start`。
3. 選擇有提供 **Persistent Disk** 的付費方案，新增 Disk，掛載路徑 `/data`（免費方案沒有永久磁碟，資料會遺失）。
4. 環境變數加入 `DATA_DIR=/data` 與 `ADMIN_PASSWORD`。
5. 部署完成後，用公司 WiFi 登入後台，確認「設定」中顯示的 IP 正確，再開啟打卡地點限制。

部署後把網址傳給員工，請他們在手機瀏覽器開啟後「加入主畫面」，用起來就像 App。

## 第一版的限制

- 不支援跨午夜的班別（例如 22:00 上班、隔天 06:00 下班會被拆成兩天）
- 公司 WiFi／位置檢查的限制請見上方「打卡地點限制 → 限制」
- 沒有排班與國定假日設定；遲到判斷以單一上班時間為準（請假時段除外）
- 請假時數只跳過週六、週日，**不會**自動扣除國定假日、颱風假或補班日；遇到這些日子請員工分開申請，或由管理員退回後重新申請
- 已核准的請假不能修改日期或時數；管理員可在「全部紀錄」撤銷（需填原因，特休自動退回），再請員工重新申請
- 特休額度依曆年計算、不自動結轉；年資只提供建議，不會自動更新額度
- 不支援請假代理人、多層簽核或 Email／LINE 通知
- 居家上班／公差只記錄 GPS，不限制地點；GPS 可被模擬定位 App 偽造
- 「異地打卡」只是標記，系統不會自動扣薪或通知，請管理員自行確認
- 薪資統整為試算，限制請見上方「薪資統整的限制」
- PIN 碼為 4 位數，適合小團隊、互相信任的環境；連續輸錯 5 次會鎖定 5 分鐘
